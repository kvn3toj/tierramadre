Manual para el Desarrollador

Desarrollo Web · Tierra Madre

Stack moderno, prompts listos para Claude Code o Lovable, 6 sprints de 1-1.5 semanas cada uno. Frontend + Backend + Middleware + Admin Panel completo.

Tu rol en el proyecto

Tú eres el dev del equipo. Construyes todo lo que NO se hace en GoHighLevel: la página web pública, las landing pages, el carrito, el checkout con Mercado Pago, el admin panel (centro de comando), el portal de embajadores y todos los Cloudflare Workers que conectan el sistema.

Buenas noticias: 80% de tu trabajo lo puedes hacer con prompts bien armados a Claude Code o Lovable. Este manual te da los prompts exactos.

Sprint 1 · Semana 1

Cimientos del proyecto

Setup del repo, Supabase, Vercel, Cloudflare. Base sobre la que construyes todo.

1

Crear repositorio GitHub (privado)

Nombre: tierramadre-system. Estructura monorepo con apps/ y supabase/. README con instrucciones de setup local.

2

Inicializar proyecto Vite + React + TS

cd apps
npm create vite@latest web -- --template react-ts
cd web
npm install
3

Instalar dependencias del frontend

npm install react-router-dom @supabase/supabase-js \
  @tanstack/react-query zustand framer-motion \
  react-hook-form @hookform/resolvers zod \
  lucide-react clsx tailwind-merge \
  date-fns recharts @tanstack/react-table \
  embla-carousel-react react-dropzone \
  @mercadopago/sdk-react

npm install -D tailwindcss@next @tailwindcss/vite \
  @types/node vitest @playwright/test \
  eslint prettier husky lint-staged
4

Configurar Tailwind 4 con tokens del diseñador

Cuando el Diseñador entregue los tokens (paleta, tipografía), pégalos en tailwind.config.ts.

Configura Tailwind CSS 4 con Vite en este proyecto. Crea tailwind.config.ts con un theme custom basado en estos tokens del Sistema de Diseño de Tierra Madre: PALETA: - emerald: 50-900 (basado en #10b981) - gold: 300-700 (basado en #fcd34d) - ink: 700-950 (oscuros para fondos) FUENTES: - sans: Inter (300, 400, 500, 600, 700, 800, 900) - serif: Playfair Display (400, 700, 900) CONFIGURACIÓN: - darkMode: 'class' - container: { center: true, padding: '2rem', screens: { '2xl': '1400px' } } - extend con animaciones personalizadas: fade-up, fade-in, scale-in Crea src/styles/globals.css con: - @tailwind directives - CSS variables para los colores (tema dark default) - Fonts importados desde Google Fonts - Reset minimal Actualiza index.html con meta tags SEO base.
5

Crear proyecto Supabase + aplicar schema

Crea proyecto en supabase.com. Anota URL + Anon Key + Service Role Key.

Instala Supabase CLI: npm install -g supabase

Aplica el schema completo de area-2-supabase.html (sección "Schema SQL").

supabase login
supabase link --project-ref XXXXX
supabase db push  # aplica la migration 001_initial
6

Configurar Storage buckets

En Supabase Studio → Storage:

  • Crear bucket products (público)
  • Crear bucket certificates (privado)
  • Crear bucket ambassadors (público)

Aplica las policies según area-2-supabase.html.

7

Configurar variables de entorno

Crea .env.local en apps/web:

VITE_SUPABASE_URL=https://xxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...
VITE_GHL_API_BASE=https://services.leadconnectorhq.com
VITE_GHL_LOCATION_ID=  # de Persona GHL
VITE_MP_PUBLIC_KEY=APP_USR-xxx
VITE_CF_WORKERS_BASE=https://wh.tierramadre.workers.dev

Crea .env.example con las mismas keys pero valores vacíos. Nunca commits .env.local a git.

8

Configurar Vercel + Cloudflare

Conectar repo GitHub a Vercel (auto-deploy en push a main). Configurar env vars en Vercel dashboard.

Crear cuenta Cloudflare. Instalar Wrangler: npm install -g wrangler y hacer login.

Sprint 1 completo cuando: proyecto corre con npm run dev, Supabase tiene schema, deploy a Vercel funciona, env vars configuradas en todos lados.

Sprint 2 · Semana 2-3

Backend completo · Supabase Edge Functions

Las 10 Edge Functions que orquestan toda la lógica server-side.

1

Aplicar RLS policies + triggers DB

Sobre el proyecto Supabase de Tierra Madre, crea migration 002_rls_policies con: 1. Habilitar RLS en todas las tablas (contacts, products, orders, ambassadors, agents, events, promotions, testimonials, message_templates, hot_leads) 2. Crear policies por los 5 roles del sistema (super_admin, admin, marketing, agente, embajador) según lo documentado en area-2-supabase.html 3. Crear migration 003_triggers con: - update_updated_at_column en todas las tablas - products_search_vector_update (full-text search) - orders_paid_trigger (suma a total_comprado, recalcula score) - ambassador_leads_match (busca contacto y asigna ambassador_id) - event_attended (incrementa eventos_presenciales/virtuales) - testimonials_auto_approve (rating >=4.5 → status approved) 4. Aplicar con: supabase db push 5. Tests SQL para verificar cada policy y trigger
2

Construir las 10 Edge Functions

Una por una, con tests. Estructura:

supabase/functions/
├── search-products/index.ts
├── create-order/index.ts
├── mp-webhook/index.ts
├── send-promo/index.ts
├── calculate-ambassador-score/index.ts
├── auto-event-invite/index.ts
├── hot-lead-detector/index.ts
├── ghl-sync/index.ts
├── invite-ambassador/index.ts
└── invite-agent/index.ts
Implementa las 10 Edge Functions de Supabase para Tierra Madre. Cada una en TypeScript + Deno con: - Manejo de CORS - Validación de input con zod - Cliente Supabase con SERVICE_ROLE_KEY - Try/catch con error handling - Logs estructurados Implementa siguiendo las especificaciones en area-2-supabase.html sección "Edge Functions" y claude-code-execution/02-custom-fields.md. Deploy cada una con: supabase functions deploy {nombre} Tests con Vitest en cada función: - Happy path - Validación de input - Manejo de errores
3

Seeds de datos de prueba

Crear supabase/seed.sql con datos para development:

  • 20 productos de muestra (mix de categorías)
  • 5 embajadoras con diferentes niveles
  • 3 eventos (1 presencial pasado, 1 virtual futuro, 1 presencial futuro)
  • 10 contactos de prueba con distintos scores
  • 5 órdenes pagadas históricas
Sprint 2 completo cuando: las 10 functions deployadas y testeadas. Llamarlas via curl devuelve responses esperadas.

Sprint 5 · Semana 6-7

Cloudflare Workers + GHL Sync

Los 4 Workers que conectan todo. Lo más técnico del proyecto.

1

Crear los 4 Workers

mkdir tierramadre-workers && cd tierramadre-workers
npm install -g wrangler
wrangler login

# Para cada worker:
wrangler init mp-webhook
wrangler init ghl-bridge
wrangler init order-orchestrator
wrangler init scheduler
Implementa los 4 Cloudflare Workers para Tierra Madre según especificación en area-4-integraciones.html: 1. mp-webhook (URL: wh.tierramadre.workers.dev/mp) - Recibe webhooks de Mercado Pago - Valida firma HMAC SHA-256 - Si payment.approved: update Supabase + update GHL + dispara workflow #08 2. ghl-bridge (URL: wh.tierramadre.workers.dev/ghl) - Recibe webhooks de GoHighLevel (ContactCreate, ContactUpdate, InboundMessage) - Sincroniza con Supabase (bidireccional) 3. order-orchestrator (URL: api.tierramadre.workers.dev/order) - POST /order/create: crear orden + preferencia MP - GET /order/:id: estado - POST /order/:id/cancel 4. scheduler (sin URL pública, cron triggers) - Cron */15 * * * *: llama hot-lead-detector - Cron 0 0 * * *: llama calculate-ambassador-score - Cron 0 9 * * *: recordatorios eventos del día - Cron 0 18 * * *: detección carrito abandonado Cada worker con TypeScript, Hono router, manejo de CORS, secrets configurados via wrangler secret put. Deploy: wrangler deploy en cada uno.
2

Configurar webhook de Mercado Pago

En Mercado Pago Developer Panel:

  • Settings → Webhooks → URL: https://wh.tierramadre.workers.dev/mp
  • Eventos: payment, merchant_order
  • Test con tarjeta de prueba MP antes de pasar a producción
3

Configurar webhook de GHL hacia Cloudflare

Cuando la Persona GHL haya terminado sus fases 1-4:

  • En GHL → Settings → Integrations → Webhooks
  • URL: https://wh.tierramadre.workers.dev/ghl
  • Eventos: ContactCreate, ContactUpdate, InboundMessage, OpportunityStageChanged
4

Conectar admin con Edge Functions

Cada acción del admin que requiera lógica server (crear embajador, enviar promo, etc.) debe llamar la Edge Function correspondiente, no manipular DB directo desde el frontend.

Sprint 5 completo cuando: pagos reales con MP → confirman en Supabase + GHL. Webhooks bidireccionales funcionando. Crons ejecutándose.
