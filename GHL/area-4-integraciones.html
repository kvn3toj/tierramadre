ÁREA 4 · MIDDLEWARE

El pegamento entre sistemas

Cloudflare Workers que reciben webhooks de Mercado Pago, GHL y Supabase, validan firmas, traducen datos entre formatos y orquestan flujos cross-sistema. Setup completo de Mercado Pago con métodos PSE, Nequi, Daviplata y tarjeta.

Objetivo

Qué construye esta área

El "tejido conectivo" del sistema. Cuando un cliente paga en Mercado Pago, alguien tiene que: actualizar la orden en Supabase, mover el contacto en el pipeline de GHL, calcular comisión, agendar el envío. Esa coreografía la hace Cloudflare Workers.

  • 4 Cloudflare Workers (microservicios stateless)
  • Setup de Mercado Pago Business + credenciales
  • Webhooks de MP validados con HMAC
  • Webhooks bidireccionales GHL ↔ Supabase
  • Worker para shipping (futuro)
  • Manejo de errores + reintentos automáticos
  • Logging y monitoreo
  • Cron triggers para tareas programadas

📦 Entregables

  • 4 Workers deployados en Cloudflare
  • URLs de webhooks documentadas
  • Secrets configurados en CF dashboard
  • Cuenta Mercado Pago Business activa
  • Webhooks de MP configurados
  • Logs accesibles en Wrangler tail
  • Tests automáticos por Worker
  • Documentación con ejemplos de payload
  • KV Storage para cachear tokens y rate limit

Los 4 Workers

Cada microservicio en detalle

Worker 1

💳 mp-webhook

Recibe webhooks de Mercado Pago cuando un pago cambia de estado.

URL: wh.tierramadre.workers.dev/mp

Eventos: payment.created, payment.updated, payment.approved

Acciones: validar HMAC → consultar pago → update Supabase → notificar GHL

Worker 2

🔄 ghl-bridge

Sincroniza datos GHL ↔ Supabase bidireccionalmente.

URL: wh.tierramadre.workers.dev/ghl

Eventos: ContactCreate, ContactUpdate, InboundMessage

Acciones: mapear custom fields → upsert en Supabase

Worker 3

🛒 order-orchestrator

Crea órdenes desde el frontend o desde el bot, genera preferencia de MP.

URL: wh.tierramadre.workers.dev/order

Métodos: POST /create, GET /status, POST /cancel

Acciones: validar carrito → insert Supabase → MP preference → URL

Worker 4

⏰ scheduler

Cron triggers para tareas programadas (no en Supabase porque no tiene cron nativo en free tier).

Triggers: cada 15min (hot leads), diario 00:00 (scoring), diario 09:00 (recordatorios)

Acciones: llamar Edge Functions de Supabase

📝 Código completo · Worker 1 · mp-webhook

// workers/mp-webhook/src/index.ts
export interface Env {
  MP_TOKEN: string;
  MP_SECRET: string;
  SUPABASE_URL: string;
  SUPABASE_SERVICE_KEY: string;
  GHL_TOKEN: string;
  GHL_LOCATION_ID: string;
  WF_POSTVENTA_ID: string;
}

async function validateMPSignature(req: Request, body: string, secret: string): Promise<boolean> {
  const xSignature = req.headers.get('x-signature') || '';
  const xRequestId = req.headers.get('x-request-id') || '';
  const dataId = new URL(req.url).searchParams.get('data.id') || '';

  // Parse x-signature: ts=...,v1=...
  const parts = xSignature.split(',');
  const ts = parts.find(p => p.startsWith('ts='))?.split('=')[1];
  const v1 = parts.find(p => p.startsWith('v1='))?.split('=')[1];

  if (!ts || !v1) return false;

  const manifest = `id:${dataId};request-id:${xRequestId};ts:${ts};`;

  const key = await crypto.subtle.importKey(
    'raw', new TextEncoder().encode(secret),
    { name: 'HMAC', hash: 'SHA-256' },
    false, ['sign']
  );
  const sig = await crypto.subtle.sign('HMAC', key, new TextEncoder().encode(manifest));
  const hex = Array.from(new Uint8Array(sig))
    .map(b => b.toString(16).padStart(2, '0')).join('');

  return hex === v1;
}

export default {
  async fetch(req: Request, env: Env): Promise<Response> {
    if (req.method !== 'POST') return new Response('only POST', { status: 405 });

    const body = await req.text();
    if (!await validateMPSignature(req, body, env.MP_SECRET)) {
      return new Response('invalid signature', { status: 401 });
    }

    const payload = JSON.parse(body);
    if (payload.type !== 'payment' || !payload.data?.id) {
      return new Response('OK', { status: 200 });
    }

    // 1. Consultar pago en MP
    const pago = await fetch(
      `https://api.mercadopago.com/v1/payments/${payload.data.id}`,
      { headers: { Authorization: `Bearer ${env.MP_TOKEN}` } }
    ).then(r => r.json());

    if (pago.status !== 'approved') {
      return new Response('OK', { status: 200 });
    }

    const orderId = pago.external_reference;

    // 2. Update orden en Supabase
    await fetch(
      `${env.SUPABASE_URL}/rest/v1/orders?id=eq.${orderId}`,
      {
        method: 'PATCH',
        headers: {
          apikey: env.SUPABASE_SERVICE_KEY,
          Authorization: `Bearer ${env.SUPABASE_SERVICE_KEY}`,
          'Content-Type': 'application/json',
          Prefer: 'return=representation'
        },
        body: JSON.stringify({
          status: 'paid',
          mp_payment_id: pago.id.toString(),
          mp_status: pago.status,
          paid_at: new Date().toISOString()
        })
      }
    );

    // 3. Obtener contact_id de la orden
    const orderResp = await fetch(
      `${env.SUPABASE_URL}/rest/v1/orders?id=eq.${orderId}&select=contact_id,ambassador_id,total_cop`,
      { headers: { apikey: env.SUPABASE_SERVICE_KEY, Authorization: `Bearer ${env.SUPABASE_SERVICE_KEY}` } }
    ).then(r => r.json());

    if (!orderResp[0]) return new Response('order not found', { status: 404 });
    const { contact_id, ambassador_id, total_cop } = orderResp[0];

    // 4. Buscar contact en GHL por contact_id custom field
    const ghlContact = await fetch(
      `https://services.leadconnectorhq.com/contacts/search?locationId=${env.GHL_LOCATION_ID}&query=${contact_id}`,
      { headers: { Authorization: `Bearer ${env.GHL_TOKEN}`, Version: '2021-07-28' } }
    ).then(r => r.json());

    if (ghlContact.contacts?.[0]) {
      const ghlId = ghlContact.contacts[0].id;

      // 5. Update GHL contact: suma total_comprado, ultima_compra
      await fetch(
        `https://services.leadconnectorhq.com/contacts/${ghlId}`,
        {
          method: 'PUT',
          headers: {
            Authorization: `Bearer ${env.GHL_TOKEN}`,
            Version: '2021-07-28',
            'Content-Type': 'application/json'
          },
          body: JSON.stringify({
            customFields: [
              { key: 'total_comprado_cop', value: total_cop },
              { key: 'ultima_compra_fecha', value: new Date().toISOString() }
            ],
            tags: ['cliente-pago-confirmado']
          })
        }
      );

      // 6. Disparar workflow #08 post-venta
      await fetch(
        `https://services.leadconnectorhq.com/workflows/${env.WF_POSTVENTA_ID}/subscriptions`,
        {
          method: 'POST',
          headers: {
            Authorization: `Bearer ${env.GHL_TOKEN}`,
            Version: '2021-07-28',
            'Content-Type': 'application/json'
          },
          body: JSON.stringify({ contactId: ghlId })
        }
      );
    }

    return new Response('OK', { status: 200 });
  }
};

Mercado Pago

Setup completo

1Crear cuenta Mercado Pago Business

  • Ir a mercadopago.com.co → Cuenta Business
  • Verificar identidad: cédula del representante legal, RUT
  • Verificar cuenta bancaria de liquidación
  • Esperar verificación (24-48h)
  • Activar métodos: PSE, Nequi, Daviplata, tarjetas Visa/MC/Amex

2Obtener credenciales API

  • Ir a mercadopago.com.co/developers/panel
  • Crear aplicación "Tierra Madre Web"
  • Copiar PUBLIC_KEY (para frontend)
  • Copiar ACCESS_TOKEN (server, secreto)
  • Copiar WEBHOOK_SECRET (para validar HMAC)
  • Tener modo PRUEBA y modo PRODUCCIÓN separados

3Configurar Webhooks

  • En el panel de developers → Webhooks
  • URL: https://wh.tierramadre.workers.dev/mp
  • Eventos a suscribir: payment, merchant_order
  • Test webhook con tarjeta de prueba antes de pasar a producción

🚀 Prompt 2 · Worker mp-webhook completo

Implementa el Worker mp-webhook en workers/mp-webhook/src/index.ts según el código completo en área-4-integraciones.html. Pasos: 1. Si status='approved': - PATCH /rest/v1/orders en Supabase: status='paid', mp_payment_id, paid_at - GET el contact_id de la orden - Buscar contact en GHL via /contacts/search - PUT GHL contact con customFields actualizados + tag 'cliente-pago-confirmado' - POST /workflows/{WF_POSTVENTA_ID}/subscriptions con contactId Manejo de errores: - Si MP API falla: log + return 500 (MP reintentará) - Si Supabase falla: log + return 500 - Si GHL falla pero Supabase OK: log + return 200 (no perder pago) Tests con Vitest: - Firma inválida → 401 - Pago no approved → 200 sin acción - Pago approved → todas las actualizaciones se hacen Deploy: wrangler deploy

🚀 Prompt 3 · order-orchestrator Worker

Implementa workers/order-orchestrator/src/index.ts con Hono router: Endpoints: POST /order/create → Crear orden + preferencia MP GET /order/:id → Obtener estado de orden POST /order/:id/cancel → Cancelar orden POST /order/create: Input JSON: { "contact": { celular, email, full_name, ciudad, direccion }, "items": [{ product_id, quantity }], "promotion_code": "TM-XKR9F2", // opcional "ambassador_id": "uuid" // opcional } Lógica: 1. Validar items contra Supabase (stock disponible + precio actual) 2. Si promotion_code: validar en promotion_codes (existe, no usado, no expirado, aplica a estos productos) 3. Calcular total con descuento 4. INSERT order en Supabase (status='pending') 5. INSERT order_items 6. Llamar MP API para crear preferencia (ver código en área-4) 7. UPDATE order con mp_preference_id 8. Devolver: { order_id, mp_checkout_url, total } Si en cualquier paso falla: rollback Supabase + return 500. Deploy con wrangler. Test con curl.
