Visión general

El ecosistema de un vistazo

Un cliente entra por cualquier canal (WhatsApp, Instagram, TikTok, landing page, evento). La IA lo califica, lo conecta con el catálogo, le ofrece productos relevantes según presupuesto, cierra la venta automática o asigna agente humano cuando se requiere. Todo registrado en un CRM central con scoring.

Multi-canal nativo

WhatsApp Business API (vía Meta Cloud + LC Phone), Instagram DM, TikTok DM, web chat. Todos los mensajes convergen en una sola bandeja en GHL, con un solo cliente identificado por celular + @ Instagram + correo.

Catálogo inteligente

Página madre construida en Vite + React con catálogo en Supabase. Cada producto se crea desde un admin panel custom con palabras clave, ocasión y rango de precio. La IA consulta el catálogo vía Supabase Edge Function y recomienda topitos, anillos o esmeraldas según lo que el cliente describe.

Lead scoring automático

Cada interacción suma puntos: presupuesto declarado, evento asistido, embajador asignado, compra previa, sentimiento en mensaje. El CRM clasifica en Frío / Tibio / Caliente / VIP.

Embajadores con comisión

Cada embajadora carga su lista de leads vía formulario. Si un lead llega y está en la lista, se le asigna automáticamente. Regla de 5 minutos: si no responde, el bot continúa la venta.

Eventos integrados

Formularios para eventos virtuales y presenciales conectados al CRM. Cada asistencia suma al historial del cliente. Segmentación automática para invitar a próximos eventos según interés y presupuesto.

Checkout automático

El bot envía link de carrito personalizado con producto + descuento si aplica. Mercado Pago procesa PSE, Nequi, Daviplata, tarjeta. Webhook confirma pago y dispara workflow de post-venta.

⭐ Decisión arquitectónica clave

¿Headless, Shopify puro, o todo custom?

Esta es la decisión más importante del proyecto. Tu intuición es correcta: Shopify se ve básico, una página custom se ve espectacular pero construir todo desde cero es titánico. La respuesta ganadora es híbrido headless: lo mejor de los dos mundos.

Opción 1 · Descartada

Shopify puro (con tema)

Todo en Shopify: catálogo + landings + checkout + tema visual.

  • ✅ Lanzas rápido (4 semanas)
  • ❌ Diseño se siente básico
  • ❌ Animaciones limitadas — no framer-motion real
  • ❌ Liquid (lenguaje de Shopify) es rígido
  • ❌ Difícil destacarse del montón
Veredicto: para marcas premium de joyería, se queda corto.
Opción 2 · Descartada

Shopify headless híbrido

Frontend custom con Storefront API + Shopify como backend invisible.

  • ✅ Diseño custom, framer-motion real

  • ❌ Aprender GraphQL de Shopify para cada query
  • ❌ Schema rígido — agregar campos custom requiere metafields
  • ❌ Pagas $29/mes a Shopify por algo que no se ve
  • ❌ Bot tiene que mapear nuestro lenguaje al de Shopify
Veredicto: agrega complejidad innecesaria para nuestro catálogo curado.

Todo custom desde cero (sin BaaS)

🔍 Cómo busca el bot — SQL directo

Edge Function de Supabase recibe la query del bot y hace un SELECT:

// Supabase Edge Function: search-products
const { intent, presupuesto, ocasion } = await req.json();

const { data: products } = await supabase
  .from('products')
  .select('id, nombre, slug, precio_cop, fotos, descripcion_corta')
  .eq('categoria', intent.categoria)
  .lte('precio_cop', presupuesto * 1.2)
  .contains('ocasion', [ocasion])
  .eq('activo', true)
  .gt('stock', 0)
  .order('destacado', { ascending: false })
  .limit(3);

👥 Lo mismo aplica para AGENTES de venta

El admin también crea agentes desde /admin/personas/agentes con el mismo flujo pero con diferencias:

🌟 Agente vs Embajador

  • Embajador: trae sus propios leads, no recibe asignaciones automáticas. Gana comisión 8-15% según nivel.
  • Agente: empleado/contratado. Recibe asignaciones automáticas según pool. Gana comisión menor 3-6% + salario fijo.
  • Embajador no tiene horario, atiende cuando puede.
  • Agente tiene horario, capacity máxima, está sujeto a SLAs.

📝 Form · Crear agente (campos extra)

  • Pool al que pertenece: Premium / Inversión / Senior / Regular
  • Horario laboral (ej: L-V 9am-6pm)
  • Capacity máxima (chats simultáneos)
  • Especialidades (gemas sueltas, anillos compromiso, etc.)
  • % comisión fijo (no por nivel)
  • Salario base (opcional)
  • Fecha de ingreso al equipo

🔄 Estados del embajador/agente

invited · Admin creó cuenta, esperando activación del correo
active · Activa y operando. Puede cargar leads y recibir asignaciones.
paused · Temporalmente fuera (vacaciones, licencia). No recibe nuevas asignaciones pero conserva leads y datos.
suspended · Caso disciplinario. No puede acceder. Comisiones pendientes congeladas.
archived · Baja definitiva. Cuenta deshabilitada pero histórico preservado para reportes.

🗃️ Qué pasa si una persona "desaparece"

Tu pregunta clave: ¿qué pasa con sus leads, ventas y puntaje cuando alguien deja de operar?

  • Datos preservados: nada se borra, queda archivado con flag archived
  • Sus leads históricos siguen atribuidos a ella en reportes
  • Comisiones devengadas se pagan según política (no se pierden)
  • Sus contactos activos se reasignan a otro embajador o quedan "libres" según decida el admin
  • Su nivel y score se congelan en su última posición
  • Reactivar es 1 click: si vuelve, retoma desde donde quedó

🧱 Middleware: Cloudflare Workers + Supabase Edge Functions

Necesitas dos cosas para orquestar todo: Edge Functions de Supabase (donde vive la lógica server-side) + Cloudflare Workers (para webhooks externos como Mercado Pago). Ambos free tier generosos.

// =========================================================
// Supabase Edge Function: search-products
// El bot llama aquí cuando un cliente describe lo que quiere
// =========================================================
import { createClient } from 'jsr:@supabase/supabase-js@2';
import { serve } from "https://deno.land/std@0.224.0/http/server.ts";

serve(async (req) => {
  const { intent, presupuesto, ocasion, ciudad } = await req.json();
  const supabase = createClient(
    Deno.env.get('SUPABASE_URL')!,
    Deno.env.get('SUPABASE_SERVICE_KEY')!
  );

  const { data: productos, error } = await supabase
    .from('products')
    .select('id, nombre, slug, precio_cop, descripcion_corta, fotos')
    .eq('categoria', intent.categoria)
    .lte('precio_cop', presupuesto * 1.2)
    .contains('ocasion', [ocasion])
    .eq('activo', true)
    .gt('stock', 0)
    .order('destacado', { ascending: false })
    .limit(3);

  if (error) return new Response(JSON.stringify({ error }), { status: 500 });

  return new Response(JSON.stringify({ productos }), {
    headers: { 'content-type': 'application/json' }
  });
});

// Cloudflare Worker: mp-webhook
// Recibe webhook de Mercado Pago cuando un pago se aprueba
// Actualiza Supabase (orden) Y GHL (contacto + pipeline)
// =========================================================
export default {
  async fetch(req, env) {
    if (req.method !== 'POST') return new Response('only POST', { status: 405 });
    const payload = await req.json();

    if (!validateSignature(req, payload, env.MP_SECRET)) {
      return new Response('invalid signature', { status: 401 });
    }

    if (payload.type === 'payment') {
      const pago = await fetch(
        `https://api.mercadopago.com/v1/payments/${payload.data.id}`,
        { headers: { Authorization: `Bearer ${env.MP_TOKEN}` } }
      ).then(r => r.json());

      if (pago.status === 'approved') {
        // 1. Actualizar orden en Supabase
        await fetch(`${env.SUPABASE_URL}/rest/v1/orders?id=eq.${pago.external_reference}`, {
          method: 'PATCH',
          headers: {
            apikey: env.SUPABASE_SERVICE_KEY,
            Authorization: `Bearer ${env.SUPABASE_SERVICE_KEY}`,
            'Content-Type': 'application/json'
          },
          body: JSON.stringify({
            status: 'paid',
            paid_at: new Date().toISOString(),
            mp_payment_id: pago.id
          })
        });

        // 2. Buscar contacto en GHL por celular
        const contacto = await fetch(
          `https://services.leadconnectorhq.com/contacts/search?query=${pago.payer.phone.number}`,
          { headers: { Authorization: `Bearer ${env.GHL_TOKEN}`, Version: '2021-07-28' } }
        ).then(r => r.json());

        // 3. Actualizar contacto en GHL
        await fetch(
          `https://services.leadconnectorhq.com/contacts/${contacto.contacts[0].id}`,
          {
            method: 'PUT',
            headers: { Authorization: `Bearer ${env.GHL_TOKEN}`, Version: '2021-07-28', 'Content-Type': 'application/json' },
            body: JSON.stringify({
              customFields: [
                { id: 'total_comprado_cop', value: contacto.total + pago.transaction_amount },
                { id: 'ultima_compra_fecha', value: new Date().toISOString() }
              ],
              tags: ['cliente-pago-confirmado']
            })
          }
        );

        // 4. Disparar workflow de post-venta en GHL
        await fetch(
          `https://services.leadconnectorhq.com/workflows/${env.WF_POSTVENTA}/subscriptions`,
          {
            method: 'POST',
            headers: { Authorization: `Bearer ${env.GHL_TOKEN}`, Version: '2021-07-28', 'Content-Type': 'application/json' },
            body: JSON.stringify({ contactId: contacto.contacts[0].id })
          }
        );
      }
    }
    return new Response('OK', { status: 200 });
  }
}
